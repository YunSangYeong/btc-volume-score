# BTC 4원칙 점수 분석기 v1.0

Bybit **BTCUSDT USDT 무기한 선물의 15분봉** 가격·거래량으로 롱/숏 점수를 계산하는 한국어 반응형 정적 웹 앱입니다. HTML, CSS, JavaScript만으로 동작하며 API 키, 유료 서버, 주문 기능이 없습니다.

## 실행

Node.js 24와 Python 3을 준비합니다. 외부 npm 의존성이 없어 `npm install`이 필요하지 않습니다.

```sh
npm test
npm start
```

`npm start`는 정적 파일을 `dist/`로 빌드하고 Python HTTP 서버를 8080 포트에 시작합니다. 로컬 개발 시 브라우저에서 `http://localhost:8080`을 엽니다. 클라우드 온보딩 UI는 이 주소의 웹 미리보기를 제공하지 않습니다. 정적 호스팅에서는 Node.js/Python이 필요하지 않습니다. ES 모듈을 사용하므로 HTML 파일을 `file://`로 직접 열지 마세요.

별도 빌드: `npm run build`. 배포 대상은 생성된 **`dist/` 전체**입니다. 저장소 루트나 `site/`만 배포하면 안 됩니다.

## 사용법

1. 페이지를 열면 공식 공개 API에서 최신 데이터를 자동 조회합니다.
2. 현재 가격은 티커의 `lastPrice`, 점수는 **최신 완료 봉까지의 데이터**를 사용합니다. 분석 기준 시각은 마지막 봉의 완료 시각이며 조회 시각과 함께 KST로 표시합니다.
3. 롱/숏 점수, 신규 진입 후보, 최근 10봉 방향, 15분/1시간 변화량과 최근 48개 점수 차트를 확인합니다. 표는 최신 12개 시점의 종가·BTC 거래량·판단을 표시합니다.
4. 포지션 없음/롱 보유/숏 보유를 선택합니다. 보유 포지션에 진입가를 입력해야 손절가와 목표가가 계산됩니다. 입력한 정보는 서버에 전송하거나 영구 저장하지 않습니다.
5. `데이터 갱신`으로 다시 조회합니다. 중복 요청 방지를 위해 갱신 후 버튼은 10초 동안 비활성화됩니다. 배경에서 API를 주기적으로 호출하지 않으며 새 봉이 생길 수 있는 시점에는 갱신 안내를 표시합니다. 페이지를 다시 열면 새로 조회합니다.

## 데이터와 장애 처리

공식 REST API `https://api.bybit.com`의 세 공개 엔드포인트를 사용합니다.

- `/v5/market/time`: 거래소 기준 시각
- `/v5/market/kline?category=linear&symbol=BTCUSDT&interval=15&limit=250`: OHLCV
- `/v5/market/tickers?category=linear&symbol=BTCUSDT`: 현재 체결 가격

먼저 얻은 서버 시각을 기준으로 `봉 시작 + 15분 <= 서버 시각`인 봉만 남깁니다. API 역순 응답은 시간순으로 정렬합니다. 현재 점수는 최근 50봉과 거래량 비교용 직전 봉을 사용합니다. 1시간 전 점수까지 비교하려면 최소 **55개 완료 봉**이 필요합니다. 일반 조회에서는 약 249개 완료 봉으로 과거 점수와 ATR을 계산합니다.

캔들 누락·중복, 잘못된 OHLCV, 최신 완료 봉 누락, API 오류, HTTP 429, 15초 타임아웃은 오류로 표시합니다. 조회 실패 시 이전 분석 숫자와 판단도 지워 오래된 결과를 최신 데이터로 오인하지 않도록 합니다. 자동 재시도나 대체 샘플 데이터는 없습니다.

거래량은 Kline `list[5]`의 **BTC 단위**를 일관되게 사용하고 USDT 거래대금인 `list[6]`은 점수에 사용하지 않습니다. [Bybit 공식 Kline 문서](https://bybit-exchange.github.io/docs/v5/market/kline)를 참고하세요.

브라우저가 Bybit에 직접 요청하므로 사용자의 네트워크·지역 제한·Bybit의 CORS 정책에 영향을 받습니다. GitHub Pages 배포만으로 이러한 제한이 해제되지는 않습니다. API가 차단되면 오류만 표시합니다. 이 개발 클라우드에서는 `api.bybit.com` 연결이 네트워크 프록시의 CONNECT 403으로 차단되어 **실제 시세 수집 성공은 아직 검증하지 못했습니다**. 테스트 fixture는 테스트에서만 사용되며 앱에 포함된 대체 데이터가 아닙니다.

## 점수 산식

| 가격 / 거래량 | 방향 |
| --- | --- |
| 양봉 / 증가 | 롱 +1 |
| 양봉 / 감소 | 숏 −1 |
| 음봉 / 증가 | 숏 −1 |
| 음봉 / 감소 | 롱 +1 |

시가=종가인 도지, 직전 봉과 거래량이 같은 봉은 중립(0)입니다. 거래량 변화율은 `(현재 거래량 − 직전 거래량) / 직전 거래량`입니다. 직전 거래량이 0이고 현재가 양수이면 무한대 증가로 가중치 1을 적용하고, 둘 다 0이면 중립 처리합니다. 고가=저가이면 몸통 비율은 0입니다.

| 항목 | 범위별 가중치 |
| --- | --- |
| 거래량 변화율 절댓값 | <10%: 0.25 / <30%: 0.50 / <60%: 0.75 / ≥60%: 1.00 |
| 몸통 비율 `abs(종가−시가)/(고가−저가)` | <20%: 0.25 / <40%: 0.50 / <70%: 0.75 / ≥70%: 1.00 |
| 시간 가중치 | 최근 1~10봉: 각 0.040 / 11~20봉: 각 0.025 / 21~30봉: 각 0.015 / 31~40봉: 각 0.012 / 41~50봉: 각 0.008 |

각 봉 점수 = 방향 × 거래량 가중치 × 몸통 가중치 × 시간 가중치.

롱 = 50 + 50 × 50봉 가중합, 숏 = 100 − 롱. 시간 가중치 합계는 1입니다. 최근 10봉은 해당 시간 가중치를 합계 1로 재정규화하여 별도 점수를 계산합니다. 4원칙 기여도는 중립 50점에 더해지는 점수(p)로 표시하며 그 합계는 `롱 점수 − 50`입니다.

과거 각 시점도 **그 시점에 완료된 50봉과 비교용 직전 봉**만 사용합니다. 미래 봉이나 현재 봉의 정보로 과거 점수를 다시 계산하지 않습니다. 변화량은 반올림 전 롱 점수의 차이(p)입니다. 판단은 원본 점수를 사용합니다. 롱·숏 점수는 소수점 이하를 각각 절사하여 정수로 표시합니다(예: 40.1 / 59.9 → 40 / 59). 따라서 표시 점수 합계는 99가 될 수 있지만 원본 점수 합계는 항상 100입니다. 변화량과 최근 10봉 점수는 기존 소수 첫째 자리 표시를 유지합니다.

### 진입과 보유 판단

- 롱 후보: 롱 ≥70, 직전 15분 대비 ≥+3p, 최근 10봉 롱 점수 >50.
- 숏 후보: 롱 ≤30, 직전 15분 대비 ≤−3p, 최근 10봉 롱 점수 <50.
- 그 외는 대기. 최근 10봉 정확히 50이면 중립입니다.

| 보유 포지션 | 유지 | 경계 | 청산 검토 | 청산 신호 |
| --- | --- | --- | --- | --- |
| 롱 | ≥70 | ≥55, <70 | ≥45, <55 | <45 |
| 숏 | ≤30 | >30, ≤45 | >45, ≤55 | >55 |

### ATR과 참고 가격

TR은 `max(고가−저가, abs(고가−직전 종가), abs(저가−직전 종가))`입니다. 첫 14개 TR 평균으로 초기화하고 이후 Wilder 방식 `(이전 ATR × 13 + TR) / 14`로 평활합니다. 조회한 완료 봉 전체를 사용합니다. 초기 손절 거리 = ATR(14) × 1.5, 목표 거리 = 손절 거리 × 2.

- 롱: 손절 = 기준가 − 거리, 목표 = 기준가 + 2 × 거리.
- 숏: 손절 = 기준가 + 거리, 목표 = 기준가 − 2 × 거리.
- 포지션 없음: 최신 완료 봉 종가를 기준으로 양 방향 참고 가격을 표시합니다. 이 가격 표시 자체가 진입 신호는 아닙니다.
- 보유 포지션: 입력 진입가를 기준으로 표시합니다. 미입력·0 이하·잘못된 입력에는 계산하지 않습니다.
- 조회 시점의 ATR을 사용하므로 재조회 시 참고선은 바뀔 수 있습니다. 진입 순간의 ATR을 고정하거나 실제 손절 주문을 추적하는 기능은 없습니다.

**백테스트 전의 실험적 기준**입니다. 수익을 보장하지 않으며 수수료·슬리피지·펀딩비는 반영하지 않습니다. 자동 주문, 거래소 계정 연결, API 키 입력 기능은 없습니다.

## 검증

`npm test`는 Node 내장 테스트 러너를 사용하며 외부 패키지가 필요 없습니다.

- 4원칙 분류, 중립 및 거래량 0 처리
- 거래량·몸통 가중치 경계값
- 50봉 시간 가중치 및 구간별 가중치
- 최대 롱/숏/중립, 기여도, 최근 10봉 정규화
- 미래 봉을 추가·변경해도 과거 점수가 같음을 검증
- 원본 롱/숏 합계 100 및 표시 점수의 소수점 절사
- 롱/숏 신규 진입과 보유 판단의 모든 경계
- Wilder ATR, 진입가 미입력 및 손절·목표 산식
- 미완성 봉 제외, 봉 누락·중복·비정상 응답
- API 수집 경로, 요청 제한, HTTP/JSON/거래소 오류

선택적 브라우저 smoke test: Python Playwright와 Chromium이 설치된 환경에서 `npm start`를 실행한 뒤 `python3 tests/browser-smoke.py`를 실행합니다. 기본 Chromium 경로는 `/usr/bin/chromium`입니다. 테스트는 **명시적인 모의 API 응답**으로 PC 1280px / 모바일 390px, 차트·기록 표시, 진입가 입력, 가로 넘침, 403/429 오류 및 실패 후 이전 결과 제거를 검증합니다. 실 API 접근이나 GitHub Pages에서의 CORS 성공을 증명하는 테스트는 아닙니다.

## GitHub Pages 배포

`.github/workflows/pages.yml`이 `main` push 또는 수동 실행 시 테스트 → 정적 빌드 → Pages artifact 업로드 → 배포를 수행합니다.

1. 변경 파일을 `YunSangYeong/btc-volume-score`의 **main** 브랜치로 커밋하고 push합니다.
2. 저장소 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다. 저장소의 Actions도 활성화되어 있어야 합니다.
3. **Actions → Test and deploy GitHub Pages** 워크플로가 성공하는지 확인합니다. 필요하면 **Run workflow**로 실행합니다.
4. 배포 완료 후 예상 주소 `https://YunSangYeong.github.io/btc-volume-score/`를 엽니다. 실제 주소는 Pages 설정이나 워크플로의 배포 결과에서 확인합니다.
5. 사용자 브라우저에서 실제 데이터가 조회되는지, 완료 봉 기준 시각과 오류 상태를 확인합니다. 네트워크 차단 시 임의 데이터가 표시되지 않습니다.

상대 경로를 사용하므로 저장소 하위 경로에서도 작동합니다. 빌드 시 JavaScript와 CSS에 콘텐츠 해시 파일명을 사용하여 배포 후 이전 파일 캐시가 재사용되지 않도록 합니다. 변경이 안 보이면 페이지를 새로고침하거나 새 시크릿 탭에서 열어 최신 HTML도 조회하세요. 워크플로 파일은 포함되어 있습니다. 실제 Pages 배포 여부는 GitHub Actions 실행 결과에서 확인하세요.
